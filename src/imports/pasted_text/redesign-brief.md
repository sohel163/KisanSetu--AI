Redesign the KisanSetu UI for EXTREME SIMPLICITY and LOW LITERACY.

The primary user may have:
- Very limited reading ability
- Very limited smartphone experience
- Limited familiarity with apps
- Difficulty understanding technical or financial terminology

The app must therefore be usable with MINIMAL READING.

IMPORTANT:
Do not simply make the existing UI prettier.

Rebuild the information hierarchy around:
ICONS + IMAGES + LARGE TILES + VERY SHORT WORDS + SIMPLE VISUAL STATUS.

The user should be able to understand the main actions even if they cannot comfortably read long sentences.

==================================================
CORE DESIGN PRINCIPLE
==================================================

“SHOW, DON'T TELL.”

Every major action should have:

BIG VISUAL ICON / ILLUSTRATION
+
VERY SHORT LABEL
+
OPTIONAL ONE-LINE EXPLANATION

Never use paragraphs for primary actions.

Avoid:
- technical terminology
- complicated menus
- dense tables
- long forms
- tiny icons
- excessive text
- nested menus
- hamburger-menu dependency
- unnecessary dashboards

Prefer:
- large buttons
- large tiles
- recognizable illustrations
- simple symbols
- visual status indicators
- voice assistance
- step-by-step flows

==================================================

==================================================

The home screen should feel like a simple visual control panel.

At the top:

👋 नमस्कार / Hello

Then show the most important action:

The user should understand:

“This button is for selling my crop.”

Use 3 levels.

💰 PAYMENT

Medium tiles:

👥 BUYER

🚚 TRANSPORT

The most important actions must visually dominate.

==================================================
NO-LITERACY FRIENDLY DESIGN
==================================================

Assume the farmer may not read English.

The UI must still make sense visually.

Use:

- recognizable images
- large icons
- color-independent status indicators
- arrows
- checkmarks
- clocks
- trucks
- money symbols
- people
- crops
- location pins
- calendars

IMPORTANT:

Never communicate meaning through color alone.

For example:

Do not use only:
GREEN = good
RED = bad

Instead use:

✓ Good
⚠ Warning
✕ Problem

with icon + text + visual treatment.

==================================================
ERROR STATES
==================================================

Errors must also be visual and simple.

Instead of:

“Network request failed. Please retry.”

Show:

📡❌

“Internet नहीं है”

“हमने आपका काम बचा लिया है।”

[ TRY AGAIN ]

Similarly:

Payment problem:

💳⚠️

“Payment अभी नहीं मिला”

Do not tell the farmer that payment succeeded unless it is actually confirmed.

==================================================
OFFLINE / LOW CONNECTIVITY
==================================================

Show clear visual states.

📡❌

“Internet नहीं है”

✓ आपका काम सुरक्षित है

🕐 भेजा जाएगा जब Internet आएगा

Never falsely show:

✓ DEAL CONFIRMED

unless confirmation actually reached the server.

==================================================

Avoid:

- giant dashboards

- tables

- technical terms

A farmer should never feel:

==================================================
MOST IMPORTANT RULE
==================================================

If a farmer with very limited literacy opens the app for the first time, they should be able to understand the following without assistance:

1. How do I sell my crop?
2. How much might I get?
3. Which buyer is better?
4. Why is that buyer recommended?
5. Is this buyer reasonably reliable?
6. What happens after I accept?
7. Has my payment arrived?

If the answer to any of these requires reading a long paragraph or navigating a complicated menu, simplify the design.

==================================================
DESIGN PHILOSOPHY
==================================================

Make KisanSetu feel like:

“WhatsApp-simple, but designed for agricultural decisions.”

Not:

“Government portal with many features.”

The final UI should be:

VISUAL
SIMPLE
CALM
LARGE
ICON-DRIVEN
VOICE-FRIENDLY
LOW-LITERACY FRIENDLY
MOBILE-FIRST

Most importantly:

DO NOT REMOVE FUNCTIONALITY.

Simplify HOW the farmer accesses it.

Every feature should remain discoverable through a clear visual tile or contextual recommendation.

The goal is not to make the app look simple.

The goal is to make the app genuinely SIMPLE TO USE.
